## 0. 확정된 전제

- **모델**: Chatterbox-Multilingual (한국어 `language_id="ko"`, MIT). "Turbo"는 한국어 미확인이라 제외.
- **입력**: `_ko_audio.md` — 이미 TTS 친화적(수식·표·기호 제거, 약어 음차). 추가 정제 거의 불필요.
- **VRAM**: 배치 변환·MD 생성과 **TTS를 동시에 돌리지 않는다**(사용자 결정). → GPU 단일 점유 가정, 동시성 게이트만 있으면 됨.
- **관찰된 문제**: 360자/40초 일괄 합성 시 끝부분 음성 품질 저하 → **청킹 필요**.

### 확정 요구사항 (사용자 명시)
- **R1. 오디오 캐싱·재사용**: 한 번 만든 오디오는 저장해 다음에도 재사용(재합성 금지). → §2 C안·§5.
- **R2. 오디오↔문서 매칭**: UI에서 지금 어느 문장을 듣고 있는지 표시. → §3-1.
- **R3. 문장 단위 내비게이션**: 다음/이전 문장으로 이동하며 듣기. → §3-3.
- (R1\~R3 모두 **청크별 오디오 파일 + 문장↔청크 매니페스트** 구조면 한 번에 충족 — 설계의 중심축.)

## 1. 핵심 결정: 청킹 전략

**문장 단위 청킹**이 품질·스트리밍을 동시에 해결.

- 분할 기준: 한국어 문장 종결(`.`, `?`, `!`, `다.`/`요.` 등) + 너무 짧은 문장은 1\~3개 묶기(자연스러운 호흡).
- 너무 긴 문장은 쉼표/접속 지점에서 2차 분할(상한 ~150자).
- `_ko_audio.md`는 이미 문단/문장이 잘 정리돼 있어 분할이 쉬움.
- 각 청크 → 개별 합성 → 짧아서 품질 일정 + 첫 청크부터 재생 가능.

**열린 질문(코덱스)**: 청크 경계에서의 운율 단절/이음새(silence padding, crossfade)를 어떻게 매끄럽게 할지?

## 2. 제공 방식 — 3가지 안

| 안 | 방식 | 장점 | 단점 |
|----|------|------|------|
| **A. 사전생성+캐싱** | 전체 청크 합성→이어붙여 `_ko_audio.mp3` 캐시→`<audio>` 재생 | 단순·견고·재청취 즉시·표준 `<audio>` 컨트롤 | 긴 논문은 첫 재생까지 대기 김(20분 논문≈12분 합성) → 백그라운드 잡 필요 |
| **B. 실시간 스트리밍** | 청크 N 재생 중 N+1 합성→순차 전송 | 낮은 TTFB(첫 문장 ~1\~2초) | 큐·순서·브라우저 순차재생 복잡, 재청취 시 재합성 |
| **C. 하이브리드(권장)** | 청크별 합성→**파일로 점진 저장**+브라우저가 생기는 대로 청크 재생 | 스트리밍 UX + 자동 캐시(재청취 즉시) + 부분 재생성 | 청크 파일 관리(인덱스) 필요 |

**권장: C**. 청크 오디오를 `audio/chunk_0001.mp3 …` 로 저장하고 매니페스트(JSON: 청크별 텍스트·시작시각·파일)를 두면 — 스트리밍·재청취·tap-to-play·seek가 모두 한 구조에서 해결됨.

## 3. UI/UX 고려사항 (사용자 질문 직답)

### 3-1. "어디 듣는 중" 표시 (현재 위치 하이라이트)
- 청크 단위로 합성하므로 **재생 중 청크 인덱스를 안다** → 본문 각 문장을 `<span data-chunk="i">`로 감싸고 **현재 청크 하이라이트 + 자동 스크롤**.
- 기존 TOC 스크롤 스파이(`activeTocId`)의 시각 패턴 재사용.
- **단어 단위 가라오케 동기화는 과설계(YAGNI)** — Chatterbox가 단어 타임스탬프를 쉽게 안 줌. **문장 단위 하이라이트가 적정**.

### 3-2. "어디까지 들었나" 표시 (청취 진행률)
- 재생 청크/전체 청크 → % → **기존 진행률 API(`/progress`) 재사용**.
- **열린 질문(코덱스)**: 읽기 진행률과 듣기 진행률을 **공유할지 분리할지**? (별도 키 권장 — 읽기와 청취는 다른 행동)
- 마지막 청크 기억 → **이어듣기(resume)**.

### 3-3. 재생 컨트롤
- 재생/일시정지, **배속(playbackRate 0.8\~2.0)**, 문장/문단 앞뒤 스킵, 스크러버.
- **tap-to-play**: 본문 문장 탭 → 그 청크부터 재생(청크 매핑 덕에 자연스러움).
- 헤딩 탭 → 해당 섹션부터 재생.

### 3-4. 모바일/백그라운드 (아이폰 핵심 use case)
- **MediaSession API**: 잠금화면/제어센터 재생 컨트롤 + 메타데이터(제목) 표시.
- 화면 잠금 시에도 재생 지속되는지 검증 필요.
- **열린 질문(코덱스)**: iOS Safari에서 순차 청크 재생 시 자동재생 정책/오디오 세션 처리.

### 3-5. 동기화 UX 디테일
- 듣는 중 사용자가 스크롤하면? → **"오디오 따라가기" 토글**(auto-follow on/off). 켜져 있으면 현재 청크로 자동 스크롤, 끄면 자유 탐색.
- Easy/원본 토글처럼 "듣기 재생 바"는 KO 전용·기존 듣기 토글과 연동.

---

## 4. 서비스 토폴로지

- **TTS 사이드카 컨테이너**(CUDA) 신설 — viewer(python:3.12-slim, GPU 없음)와 분리.
- viewer는 TTS 서비스에 요청을 프록시하거나, TTS 워커가 청크 오디오를 논문 폴더에 쓰고 viewer가 정적 서빙(`_ko_audio.md`처럼).
- **GPU 동시성 게이트**: 변환(MinerU) 가동 중엔 TTS 잡을 큐잉(공유 락/세마포어 또는 큐). 사용자 전제(동시 실행 안 함)를 시스템이 강제.

---

## 5. 캐싱/freshness
- `_ko_audio.meta.json` 패턴 계승: 청크 오디오 캐시에 **소스 sha256/mtime** 기록 → `_ko_audio.md` 수정 시 무효화·재생성.
- 청크 단위 저장이면 변경된 문단만 부분 재생성 가능(선택).
