전면 컷오버는 루브릭 비열등성 조건 #2(critical 축에서 1점 이상 낮은 pair 0개)를 tech 편에서 만족하지 못한다.

## 라운드 1 — FAIL, 그리고 그것이 알려준 것

1. **tech: 소스 복사본 생산.** 산문 문단의 **100%** 가 소스와 한 글자도 다르지 않았다. 자수비 1.02x 라
   당시 게이트를 통과했고, Codex 자기보고도 `verify_verdict:"PASS"` 였다 — **거짓 보고가 아니라 게이트가 없었던 것**.
   원인 추정: 소스가 이미 한국어 번역본이라 스킬의 "재진술 금지"를 "손대지 말라"로 오독.
2. **viz: 그림 대량 유실.** 23개 중 21개(91%)를 버리고 분량도 0.52x.
3. **prose: 정상.** 재작성·용어 인라인 해설·논증 구조화 모두 제대로 됐다.

**핵심 관찰: Codex 는 검증기 판정을 따른다.** 따라서 스킬 산문을 고치는 것보다 게이트를 조이는 것이 레버리지가 크다.

## 라운드 1 → 2 사이에 바꾼 것

- `scripts/verify_explainer.py` 하드게이트 3종 신설 (레거시 120편으로 임계 보정):
  - `source-copy` — 산문 문단 중 소스와 동일한 비율. ≥70% FAIL. (참고문헌·이미지 블록 제외)
  - `ratio` — 의심(REVIEW)과 소실(FAIL) 분리. 한국어 <0.5 / 외국어 <0.4 는 FAIL.
  - `image-refs` — 손실 ≥50% 이고 3건 이상이면 FAIL.
- `.codex/skills/paper-explainer/SKILL.md` 에 「실측 실패 양상」 절 추가(위 두 사례를 구체적으로 명시,
  "재진술 금지 ≠ 재작성 금지"), Quality Checks 를 **FAIL 이 사라질 때까지 검증기 반복**으로 변경.

- **남은 미달 — tech 편 coverage**:

  마크다운 표까지 세면 **3/4 보존**이고 Codex 는 HTML 표를 마크다운으로 변환했다(Rule 7 이 권장하는 방향).
  실제 주 원인은 **인라인 수식 61% 유실 + 전반적 압축**이다. 표는 부차적(1개 순손실).

## Claude baseline defect (기준선 원칙에 따라 별도 기록)

- **viz 편에서 Claude 가 이미지 18/23(78%)을 유실해 FAIL.** Codex 에게 이 실패를 요구하지 않는다.
- 신설 게이트로 레거시 120편을 재검사한 결과 FAIL 6편(5%) — 전부 실제 결함
  (AI Index Report `0.05x`·이미지 434건 유실, FEATUREBENCH `0.28x`, YAML 헤더 누락 2편 등).
  **해설판 전반의 품질 문제이지 Codex 이관 고유 문제가 아니다.**

## 백로그 구성 (의사결정 재료)

현재 해설판 백로그 20편: **산문형 18편**(400\~14K자 웹 글·뉴스), 기술형 2편(9.6K·8.8K자, 표 위주).
**Codex 가 미달한 장문 기술 논문(69K자, 수식 1400+, 결과 표 다수)은 현재 백로그에 0편**이다.
단 DSBA 플레이리스트 폴링이 arXiv 에이전트 논문을 계속 넣으므로 장래 유입 가능성은 있다.

## 결론

- **전면 컷오버 조건 미충족.** 루브릭 비열등성 #2 를 tech 편이 만족하지 못한다.
- **실패 영역은 좁고 특정 가능하다**: 장문 + 수식 밀집 기술 논문에서 **인라인 수식을 버리며 압축**한다.
- **게이트가 이 실패를 자동 반려하지 못한다**:
  - `ratio` — tech r2 는 `0.50x` 로 FAIL 문턱(<0.5) **바로 위** REVIEW.
  - `math-coverage`(신설) — 39% 로 REVIEW 는 뜨지만 **FAIL 로 못 올린다**. 레거시 Claude 산출물의
    수식 보존율 분포가 넓어(p25 0.31, 17편 중 5편이 0.5 미만) FAIL 임계를 두면 정상 산출물까지 반려된다.
  - `table-coverage`(신설) — 표는 3/4 라 통과. 이 축은 문제가 아니었다.
  즉 같은 유형이 배치로 들어오면 **REVIEW 로 통과한다**. 사후 로그 감시로만 잡힌다.

# 라운드 3 (사용자 승인 "A로 진행") — tech 1편 재생성

r3 는 피어 권고대로 3편을 다시 만들지 않고 실패가 국소화된 **tech 1편만** fresh 생성했다.
사전에 게이트를 강화(`number-coverage`·`table-row-coverage`·blocking/advisory 분리)하고
스킬에 Evidence Inventory 절차 + 수치 덤프 금지를 넣었다.

## 결과: 게이트는 작동, 산출물은 여전히 미달

에이전트가 **스스로 게이트를 돌려 `source-copy` FAIL 을 탐지하고 publish 를 거부**했다
(`result:"failed"`, `notes:["source_copy_gate_failed","final_not_published","part_file_only"]`).
프로덕션 경로에는 아무것도 나타나지 않았다 — 설계대로다.

## 3라운드 궤적 (tech 편, 소스 69,336자)

| | 자수 | ratio | 소스 복사 | 수치 recall | 표 행 소실 | 수식 |
|---|---:|---:|---:|---:|---:|---:|
| **Claude (기존)** | 73,706 | 1.06x | **2%** | **99.3%** | 0/83 | 623/584 |
| Codex r1 | 70,668 | 1.02x | 100% | 100% | 0/83 | 589/584 |
| Codex r2 | 34,687 | 0.50x | 0% | 75.2% | 16/83 | 229/584 |
| Codex r3 | 70,285 | 1.01x | 98% | 100% | 0/83 | 586/584 |

**핵심 소견**: Codex 는 **두 극단을 오갈 뿐 Claude 가 있는 중간에 도달하지 못한다.**

- 복사하면 coverage 가 완벽해진다(r1, r3) — 아무것도 안 빠지지만 해설판이 아니다.
- 재작성하면 coverage 가 무너진다(r2) — 수치 25%·수식 61%·표 행 16개가 사라진다.
- Claude 는 복사 2% 에서 coverage 99.3% 를 달성한다. **중간은 도달 가능한 지점이다.**

세 라운드의 지시 강화는 Codex 를 극단 사이에서 이동시켰을 뿐 중간으로 데려가지 못했다.
r3 에서 Evidence Inventory 를 넣자 coverage 를 되찾았지만 그 수단이 복사였다.
이는 프롬프트 문제라기보다 **이 문서 유형(장문 한국어 번역본 기술 논문)에 대한
gpt-5.6-sol 티어의 한계**로 보인다.

## 실패 유형의 실무 비중

| 구간 | high-risk 비율 |
|---|---|
| 현재 해설판 백로그 20편 | **1편(5%)** — 그마저 8,773자 소형 |
| 최근 유입 60편 | **1편(2%)** |

(high-risk = 3만자↑ OR 표 수치 셀 20↑ OR 수식 20↑)

Codex 가 실패하는 문서 유형은 실무에서 **희소**하다. tech 시험편(69K자, 수식 584, 표 행 83)은
최근 유입에 유사 사례가 없는 상위 이상치다.

## r3 결론

- **루브릭 비열등성 미충족**은 변함없다 — tech 편에서 Codex 는 Claude 보다 명확히 낮다.
- 그러나 **게이트가 이제 이 실패를 확실히 잡는다**: r1(복사)·r2(coverage 소실)·r3(복사) 모두 FAIL.
  프로덕션에 나쁜 산출물이 새어 나가지 않는다.
- 그리고 **실패는 희소하다**(유입의 2%).
- 산문·시각 문서에서는 Codex 가 Claude 와 동등하거나 우세하다(그림 보존 23/23 vs 5/23).

선택지와 권고는 사용자 보고 및 `HANDOFF.md` 「다음 세션 시작점」에 정리했다.
